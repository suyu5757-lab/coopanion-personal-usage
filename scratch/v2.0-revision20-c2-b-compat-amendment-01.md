### 3. 修订后的精确兼容矩阵

| 原始数据库状态 | C2-B 支持合同 | 必要证据 |
|---|---|---|
| 合法空库（无未知用户表/view/trigger） | **支持**：原子初始化为 v4 | 初次建库；持久结构、quick_check/外键；重开幂等 |
| 可核验真实 schema v2 | **支持**：v2→v3→v4 单事务迁移 | 真实 v2 DDL/fixture；旧行逐项不变；故障回滚、可重试 |
| 可核验真实 schema v3 | **支持**：v3→v4 单事务迁移 | 真实 v3 DDL/fixture；旧行逐项不变；故障回滚、可重试 |
| 严格匹配的 schema v4 | **支持**：正常打开与幂等 no-op | schema/index/约束完整，旧 state 不重写 |
| `user_version=1`，没有可验证历史 DDL/fixture | **不支持自动迁移**：`v1_unsupported_fail_closed` | 明确拒绝，文件/原有数据不改写，**不能记为 v1→v4 PASS** |
| 其他版本、损坏或部分/冲突结构 | **不支持自动修复**：fail closed | 错误可见，不能当空库重建或暗改 `user_version` |

**必须保持：** SQLite v4 schema/typed APIs、完整 `(bankId, endpoint, documentId)`、epoch/fence/revision/digest、多父来源、`unknown/missing/ambiguous/stale`、`actualEvidenceUsed=unknown`、源正文不重复入 SQLite、旧 durable rows 和 PARTNER sidecar 原职责、事务 ACID、异常回滚、重启读取与幂等性。

### 4. B02、MEM-08、R2 与 C2-B 放行标准的精确修订

**B02（修订）：**

- `B02-SUPPORTED-MIGRATION`：以真实、可溯源的 v2 fixture 完成到 v4 的单事务迁移，旧记录完整、schema/版本符合预期；并与 B01 的 v3、B03 的 empty 路径组合证明全部已支持迁移范围。
- `B02-UNSUPPORTED-V1-SAFETY`：对未经证实的 v1 数据库明确拒绝，拒绝前后数据库内容哈希/版本保持一致，无静默重建、数据删除或升级。此项是 **unsupported fail-closed PASS**，不是 v1 migration PASS。
- B02 综合记为 `PASS_LOCAL_REVISED_SCOPE` **仅在上述两项各有可复核独立证据**时；不得仅通过修改文档直接改写测试结果。

**MEM-08（修订）：** v4 来源依赖存储、完整 identity、多父、unknown、安全迁移空库/v2/v3、重启及回滚成功，且未知 v1 正确拒绝。其结果可为 `PASS_LOCAL_REVISED_SCOPE`，但不暗示正式 App、真实生产数据库已验收。

**R2 持久存储兼容（修订）：** 用真实临时 SQLite（空库、v2、v3、v4）检验已支持路径；对 v1 检验不变更的拒绝行为。逐项保留旧 Outbox、revision、Forget、activation/mention、derived state、PARTNER sidecar 的合法边界；迁移失败 rollback/retry，读写与跨 namespace 约束不变。

**C2-B 局部放行（修订）：** `C2_B_FOCUSED_PASS_LOCAL` 需同时满足：B01–B12 按**修订后的 B02**全覆盖，所有支持路径原子与非退化；R2 必要局部回归无新关联失败；报告与 Git/资源/保护项完整；没有对正式生产数据操作。用户批准此兼容范围**不是自动认可 PASS**。Codex 必须复核、更新唯一账本并提交可追踪证据，供用户审查。
